# 0.2.x Prioritized Issues

Last updated: 2026-02-11

## Priority Order
1. RMD-020: First-class subagent orchestration
2. RMD-021: Git worktree compatibility guarantees
3. RMD-022: Compound loop enforcement in contribution flow

## RMD-020: First-Class Subagent Orchestration
- Priority: P0
- Status: In progress (implementation PRD + Phase A/B completed in current branch; Phase C pending)
- Why now: unlocks safe delegation and is a blocker for multi-agent scale.
- Scope:
  - define explicit node/graph attributes for subagent delegation and task contracts,
  - harden `stack.manager_loop` beyond polling stub behavior,
  - persist deterministic handoff/telemetry artifacts for each delegated unit of work.
- Deliverables:
  - handler/runtime changes,
  - schema/lint updates,
  - docs updates with examples.
- Acceptance criteria:
  - manager loop can execute a delegated task cycle to completion without manual state injection,
  - artifacts show task input, delegated prompt/contract, result, and lock decision,
  - golden tests cover success, retry, and failure/reopen paths.
- Dependencies:
  - none (foundational for remaining 0.2.x work).

## RMD-021: Git Worktree Compatibility Guarantees
- Priority: P1
- Status: In progress (docs + CI parity check implemented; strict CI no-skip mode added on 2026-02-11)
- Why now: teams need isolated branches/worktrees without workflow regressions.
- Scope:
  - document supported worktree usage and caveats,
  - validate logs/checkpoints/manifests work correctly when executed from worktrees,
  - add CI coverage for worktree-path execution parity.
- Deliverables:
  - docs section in README,
  - tests and CI job proving parity.
- Acceptance criteria:
  - test workflow passes in primary checkout and temporary worktree with matching normalized outputs,
  - checkpoint/resume and artifact pathing work from worktree roots,
  - CI includes an explicit worktree-parity job.
- Dependencies:
  - can run independently of RMD-020.

## RMD-022: Compound Loop Enforcement in Contribution Flow
- Priority: P1
- Status: In progress (PR body compliance gate + weekly report generator/report set added on 2026-02-11)
- Why now: OS scaffolding exists; enforcement drives adoption and measurable value.
- Scope:
  - enforce required plan/review/compound links in PRs,
  - operationalize weekly metrics reporting from `docs/metrics/compound-rate.md`,
  - add lightweight compliance checks to contributor workflow.
- Deliverables:
  - PR template/check updates,
  - optional CI check or script for artifact-link presence,
  - weekly report cadence definition in docs.
- Acceptance criteria:
  - at least one merge gate validates required artifact links,
  - compliance is measurable and reaches >90% over a 4-week window,
  - weekly metrics reports are generated for 4 consecutive weeks.
- Dependencies:
  - existing templates and `AGENTS.md` (already present).

## Suggested Execution Strategy
- Iteration 1: deliver minimum viable RMD-020 with end-to-end deterministic delegation.
- Iteration 2: complete RMD-021 parity tests and docs.
- Iteration 3: enforce RMD-022 with checks + weekly reporting loop.
